# Kivo 桌面端说明

## 1. 产品与平台

桌面端采用 Go + Wails 2 的原生窗口和系统 WebView，不额外分发 Chromium。页面使用原生 HTML / CSS / JavaScript，无外部 CDN。界面为紧凑单列、顶部连接开关、分组节点列表、首页 / 配置 / 状态 / 设置四个底部标签。它不是一个浏览器快捷方式。

桌面端、CLI 和 Web 共用后台及配置。桌面可单独运行，发行桌面包同时附带 CLI，CLI 内嵌 Web；最终用户无需安装 Go 或 Node.js。Mihomo 仍需在线安装或导入官方本地包。

| 平台                              | 运行依赖                            | 验收边界                                               |
| --------------------------------- | ----------------------------------- | ------------------------------------------------------ |
| Windows AMD64                     | Microsoft WebView2 Runtime          | 本机原生构建与窗口测试                                 |
| Windows ARM64                     | ARM64 WebView2 Runtime              | 提供构建目标；仍需 ARM64 实机验收                      |
| macOS Intel / M2 等 Apple Silicon | 系统 WKWebView                      | 提供 Universal 原生构建流水线，需 Mac 验收、签名与公证 |
| Linux AMD64 / ARM64               | GTK 3、WebKitGTK 4.1 与图形桌面会话 | 提供原生构建流水线，需发行版实机验收                   |

无图形桌面的 Linux 服务器应使用 CLI / Web。系统代理接入依赖桌面环境；不支持时明确提示，不把内核运行误判为代理开启。当前产物尚未签名，不要为安装它全局关闭系统保护。

## 2. 启动与目录

Windows 解压桌面包，双击 `kivo-desktop.exe`，不弹出终端。缺少 WebView2 时按框架提示前往微软官方页面安装。Mac 使用 `.app`，Linux 在图形桌面运行 `./kivo-desktop`。

默认配置目录与 CLI 相同，Windows 为 `%APPDATA%\Kivo`；如果存在原 `ProxyPilot/config.json`，继续复用旧目录，不复制或抛弃已有配置。Windows 的 `desktop-webview/` 是 WebView 缓存和主题偏好，不是订阅配置。真实配置仍在 `config.json`，后台日志在 `logs/controller.log`。

```powershell
.\kivo-desktop.exe --data-dir E:\KivoData
```

```bash
./kivo-desktop --data-dir /path/to/kivo-data
```

同一数据目录只开一个桌面窗口；再次启动唤起原窗口。不同目录须设置不同的 Web、内核控制和混合代理端口。打开桌面不新增自动接入偏好；后台继承已经保存的恢复设置。升级前先退出旧 UI，使用 CLI `/shutdown` 停止旧后台。

## 3. 完整使用流程

1. 设置 → Mihomo 内核 → 安装 / 更新。显示实际下载字节、总量和速度；未知总量显示不定进度。仅后台确认完成才表示安装成功。
2. 右上角 `+` 进入独立的添加订阅页。普通订阅只需填写地址，名称可以自动生成；密码保护订阅填写解密密码（默认使用已支持的 AES-CBC 兼容格式）。高级设置提供下载认证、age 私钥、分组、User-Agent、更新周期、节点过滤与连接覆盖。
3. 首页订阅标题右侧的更新按钮按该订阅的默认方式更新，结果就在该订阅下显示。顶部“更新订阅”可批量选择直连或代理；默认尊重各订阅的设置。结果显示路径、解析节点数和失败原因；未知数量不冒充 0。原本停止的内核会临时启动并恢复停止。
4. 设置 → 启动内核。首页展开订阅、搜索并点击节点。离线缓存只供查看，不允许切换。
5. 打开连接开关，验证代理入口、备份并接入系统代理。已有其他代理 / PAC 时先确认，不静默覆盖。
6. 点击连通测试，状态页分别显示直连、代理入口、固定节点出口。打开开关不等于所有网站均可访问。

直连只绕过 HTTP 系统代理 / 环境变量代理，无法绕过系统 VPN、TUN 或网络网关。代理更新需要已有可用节点。更新路径会保存为订阅偏好，不是仅本次有效。AES / age 是内容解密，不是节点协议；age 需要相应格式的私钥，不是任意口令。

### 订阅编辑与凭据安全

- 返回按钮 / Esc：未修改直接返回；有草稿时先确认是否放弃。返回恢复原列表滚动位置和展开状态；后台轮询不覆盖输入。
- 编辑已有订阅：真实 URL、密码和私钥不回填到页面。地址或凭据留空表示保留；高级设置将认证或解密设为“无需认证 / 未加密”才会清除对应凭据。
- 下载认证和内容解密可以同时存在，例如 Basic + AES；解密密码不会作为 HTTP 认证发送。切换认证类型必须重新提供凭据，避免跨协议复用。旧 CLI 的单一 `--auth` 仍可使用，但不能用它覆盖同时使用两层凭据的订阅。
- 过滤使用 Go/RE2 正则，例如保留 `香港|日本`、排除 `过期|剩余流量`，不支持前后查找。过滤不是网站分流规则。
- UDP、TCP 快速打开、节点证书验证均默认“跟随订阅”，不会覆盖远端节点参数。跳过节点证书验证有安全风险，也不会影响下载订阅时的 HTTPS 验证。
- User-Agent 默认 `Clash.Meta`，这是请求客户端标识，不是代理服务器地址。当前不猜测任意 AES 格式，也不把节点数量上限映射成文件下载字节限制。
- 多窗口修改存在冲突时拒绝覆盖；输入保留，返回后重新打开编辑页读取最新版本。配置已保存但内核重载失败会单独警告，避免重复添加。
- 旧后台不支持新版字段时，桌面会阻止保存。升级时退出旧桌面、用 CLI `/shutdown` 停止旧后台，再运行新版；原数据目录保留。
- 自 v0.3.3 起使用 V3 配置结构，首次加载 V1/V2 时先保留原文件为 `config.v1.backup.json` / `config.v2.backup.json`，再升级。备份也包含敏感凭据，请勿分享。旧程序会拒绝新配置，避免静默丢失新字段；同时使用 CLI 时也应更新 CLI。不要在旧后台仍运行时启动新版。

### 分层订阅 API

`POST /api/v1/subscriptions` 使用 `downloadAuth: {type, username, secret}` 和 `decryption: {type, secret}` 分别设置两层凭据；普通订阅的类型均为 `none`。`options` 支持 `userAgent`、`filter`、`excludeFilter`、`udp`、`tfo`、`skipCertVerify`。后三项为 `default/on/off`。

`PATCH /api/v1/subscriptions` 额外携带 `reference` 和查询返回的 `revision`。凭据子对象中省略 `secret` 保留旧值，设 `type: none` 清除对应层；`options` 为完整选项对象替换，省略则保留。不能混用旧 `authType/username/secret` 字段与分层凭据字段。公开查询只返回类型、选项和版本摘要，不返回秘密。

## 4. 状态判断

首页第一行在连接关闭时显示“未连接”，连接开启后显示当前节点名称；直连模式显示“直连模式”，未选节点时显示“已连接 · 未选择节点”。开关反映系统代理是否接入 Kivo，节点名本身不代表该节点可用。运行异常时首行下方给出提示，完整的内核、系统代理和三条检测路径请到“状态”页查看。

首页“联网检测”右侧只显示上次检测时间；尚未检测显示“尚未检测”，跨天记录带日期。检测结果超过 2 分钟后不再作为“当前可上网”的证据，也不继续显示成功色；这不会自动关闭代理。到“状态”页可查看过期原因和具体检测结果，点击首页“联网检测”可重新检测。

紫色单选标记只代表选择的节点。节点测速、系统代理配置、联网检测是三种不同状态。

## 5. 页面操作

- 首页：连接 / 断开、规则 / 全局 / 直连模式、联网检测、节点分组搜索 / 选择 / 测速 / 详情与订阅更新。
- 配置：按分组列表管理订阅添加 / 编辑 / 启禁 / 删除、单订阅与分组更新 / 检查；订阅分组可重命名并自动更新引用。路由配置可创建、关联、解除关联、使用；规则可添加、编辑、上下移动或删除。内置方案和规则组受保护，旧配置可“恢复内置方案”。
- 状态：不折叠运行状态、三路径联网检测、环境诊断和内核日志。进入页面即自动执行只读诊断并读取最近 200 行内核日志；页面可见时每 1 秒读取新增日志，离开页面或隐藏窗口后停止轮询。可手动重新诊断或刷新日志。实时日志来自 Mihomo 内核的本机有界缓存；内核未运行时可能没有新日志。不伪造流量曲线或带宽统计。
- 设置：各分组直接展开显示系统 / 明 / 暗主题，代理端口、LAN、TUN、下载代理与重试；内核下载进度、原生文件导入、版本切换 / 删除、启停；Web Token 即时变更、备份恢复与退出。

内置路由：`rule` 规则、`global` 全局、`direct` 直连、`bypass-cn` 绕过大陆、`proxy-only` 仅指定地址代理、`bypass-list` 指定地址直连。规则组必须关联活动配置才生效；配置卡片上的规则组标签可直接解除关联，同组规则按列表顺序匹配。内置项不能删除；自定义方案须先切换后删除，正在被引用的规则组须先解除关联。

添加订阅页按“左侧字段名、右侧输入”的整行布局排列；默认显示地址、名称、解密密码、更新方式，高级设置按需展开。编辑订阅地址留空保留原值，不把脱敏 URL 保存成真实地址；凭据留空保留原凭据，认证变更按后台校验。Token 不回显原值；留空可关闭鉴权，确认前提醒访问范围风险。桌面端自动读取新 Token，无需重启。

配置可能重载运行中的内核。变更串行执行，进行安装或代理事务时阻止直接关闭窗口。TUN 可能需管理员权限，勿与其他代理的虚拟网卡冲突。

## 6. 退出与恢复

- 标题栏 `×` / 隐藏到托盘：托盘就绪后只隐藏窗口，桌面进程、托盘、后台与代理继续运行；单击 / 双击托盘或再次启动程序恢复原窗口。
- 退出桌面（保留代理）：真正关闭桌面进程与托盘，后台及当前代理仍保留；不是隐藏到托盘。
- 断开并退出：恢复受管系统代理、停止内核、关闭 UI；后台管理服务保留供 CLI / Web 使用。冲突时保留窗口，不强制覆盖其他程序的设置。
- 关闭全部后台：CLI `/shutdown` 或 `kivo shutdown`。

### 托盘状态与菜单

Windows 在右下角通知区域（也可能收在 `^` 隐藏图标中），Mac 在顶栏；右键打开菜单。Linux 使用 StatusNotifierItem / DBusMenu，需要桌面托盘宿主；GNOME 通常需启用 AppIndicator 支持。只支持旧 XEmbed 的桌面不提供该托盘协议时保持普通窗口模式，不自动安装扩展或更改系统设置。

托盘状态只概括系统代理接入为“已启用 / 未启用”；后台不可读时显示“状态暂不可用”，不把“未检测”误当成代理未开启。菜单仅有一个动态代理按钮：关闭时“开启代理”，接入后“关闭代理”；TUN 也只有一个动态按钮，按最新配置显示“开启 TUN 模式”或“关闭 TUN 模式”。开启 TUN 需内核运行，停止后仍可从托盘关闭已配置的 TUN；操作仅提交 TUN 字段，不覆盖端口和下载设置。TUN 可能需要管理员权限，菜单显示开启并不等于虚拟网卡已成功接管流量。可检测连通性、打开 Web、保留代理退出或断开并退出。托盘触发检测不会打开主窗口；详细结果到状态页查看。图标角标：灰色未接入、紫色已接入、红色接管异常 / 后台不可读、黄色操作中。接入不保证所有网站可用；直连模式仍需到状态页确认路由。

状态每 5 秒读取本机后台，即使窗口隐藏也更新，不自动发起外网检测。开启代理沿用后台的启动、备份与连通检查；替换其他代理 / PAC 前要求确认；恢复失败不强制退出。安装和代理事务共用互斥门，禁止重复操作或中途退出。

设置页显示托盘是否可用。初始化未完成时暂不允许隐藏；注册失败时 `×` 回退为退出 UI（后台保留），隐藏按钮禁用。Windows Explorer 或 Linux 托盘宿主丢失时恢复主窗口；初次失败会在 1 / 4 / 9 / 16 秒后重试，连续五次失败后停止自动重试，可点“重试托盘”；运行中持续不可用会重新初始化。再次启动同一数据目录只恢复窗口，不创建重复托盘。Windows 托盘原生确认框返回 `Yes/No`，程序已按平台返回值处理，点击“是”才执行退出。

有未恢复备份时，设置页显示恢复按钮。外部手动代理仍指向已停止端口、恢复冲突等情况按提示处理，不能将未恢复显示为成功。

### 页面刷新与草稿

启停只刷新受影响的状态、节点，不重新加载整个页面。节点列表增量更新，保留展开、焦点及滚动；每组先显示 80 个节点，支持继续加载。内容滚动区域始终预留滚动条空间，展开订阅时页面不会横向跳动；首页连接、代理模式、联网检测三行等高。各标签保留浏览位置；配置分为“订阅”和“分流规则”，设置分组直接展开，代理设置保存按钮位于表单右下角。窗口默认 440×956，最小 390×680、最大 600×1080；默认尺寸对应 iPhone 17 Pro Max 的逻辑显示区域，实际桌面标题栏会占用少量空间。

变更时显示固定位置的进度提示，不把节点列表推下去。连接期间区分“正在连接”“已接入 · 正在检测”“正在断开”。后台确认成功但状态读取失败时，明确提示“操作已生效，部分状态暂未刷新”，保留重试入口；节点读取失败不会把整个后台误标为离线。

网络设置草稿在轮询、切换页面和其他操作期间保留。保存携带设置版本；如果 CLI / Web 已修改设置，拒绝覆盖并保留草稿。点击“放弃草稿并重新读取”之前请记下需要保留的输入。模式切换只提交模式，不覆盖端口、TUN 等字段。

升级到 v0.3.2 前，请先在旧 CLI 执行 `/shutdown`，并退出旧桌面，再启动新包。此操作会短暂中断代理，配置与订阅会保留。新版会阻止向旧后台发送不兼容的局部设置请求，并在设置页提示升级。仅关闭旧桌面窗口不会退出其后台。

## 7. 架构与安全

```text
desktop/main.go                 原生窗口、文件选择、主题、生命周期
  └─ internal/desktop           本机 API 白名单、最新凭据、安装进度流
      └─ internal/controller    与 CLI 共用后台启动和复用逻辑
          └─ server → app.Service → Mihomo / 平台系统代理
desktop/frontend                独立紧凑界面与可测试的纯状态模型
  └─ server.EmbeddedAssets()    复用离线中文字体
desktop/tray.go                 状态派生、有限命令队列与后台 API 复用
  └─ desktop/internal/tray      Windows / AppKit / D-Bus 原生托盘适配
```

桌面独立 Go 模块，主模块仍为纯标准库，CLI 六平台交叉构建不受影响。原生桥只接受明确的 API 方法 / 路径，不允许任意 URL、外部主机、重定向、内部解密接口或页面透传 shutdown；本地 HTTP 不使用系统代理。每次读取最新 Web Token，Go 不向 JS 返回原凭据。批量失败保留部分成功结果。

无外部字体、无浏览器远程调试端口。名称和日志用 `textContent`，不解释成 HTML。Wails 只使用默认可信本地 origin，不扩展外部绑定来源。关闭 UI 与停止后台分离；没有额外数据库或第二套代理业务状态。

隐藏与恢复窗口串行执行，防止宿主丢失与手动关闭竞态。恢复窗口刷新状态但不覆盖未保存的设置表单；退出前删除原生托盘图标。托盘只显示节点名称，不展示订阅地址、密码或 Web Token。

## 8. 开发与构建

开发需 Go（版本按 `desktop/go.mod`）和 Node.js（测试）；用户不需要。Wails 固定 `v2.15.0`，不使用 v3 beta。Linux 需 gcc / pkg-config / GTK / WebKit 开发包，Mac 需 Xcode Command Line Tools。

```powershell
.\scripts\build-desktop.ps1 -Version 0.3.6-desktop-preview -Commit <提交号> -BuildDate <UTC时间>
.\scripts\build-desktop.ps1 -Architecture arm64
```

```bash
# Mac Universal（包含 Intel 与 M2 等 Apple Silicon）
TARGET=darwin/universal sh scripts/build-desktop.sh
# Ubuntu 24.04
sudo apt-get install build-essential pkg-config libgtk-3-dev libwebkit2gtk-4.1-dev
BUILD_TAGS=webkit2_41 sh scripts/build-desktop.sh
```

```text
go test ./...
go vet ./...
node --test scripts/test-desktop.mjs scripts/test-desktop-ui.mjs scripts/test-web.mjs
cd desktop
go test ./...
go vet ./...
```

Linux 桌面模块 `go test` / `go vet` 同样需要 `GOFLAGS=-tags=webkit2_41`。构建必须在对应系统进行，不能将 CLI 的无 CGO 六平台交叉编译视为桌面实机验证。

冒烟测试必须独立目录、独立端口，关闭自动代理 / 内核启动且无代理备份：`kivo-desktop.exe --data-dir <隔离目录> --smoke-test`。页面验证原生桥、资源和四标签后写 `desktop-smoke.json` 并退出 UI，测试人员另行关闭隔离后台；不能用真实用户配置测试。

`desktop.yml` 提供五平台目标原生 CI 与下载 artifact，不自动发布 Release、创建标签或签名。配置了流程不代表已经运行成功；正式发布前须完成 Mac / Linux 原生验收。

### macOS 测试包

`macos-package.yml` 在桌面开发分支推送后构建 Universal 应用和 CLI，检查两者的 `x86_64` 与 `arm64` 架构，并用 `ditto` 压缩以保留 `.app` 的可执行权限和符号链接。artifact 包含 `kivo-desktop-darwin-universal.zip`、未公证的 `Kivo-Installer-darwin-universal.pkg` 与 `SHA256SUMS`。正式版本标签的统一 Release 工作流也会发布这些包。

在 Mac 上解压 ZIP，将 `Kivo.app` 拖到“应用程序”，并可在解压目录执行 `./kivo`；PKG 测试包可同时安装两者。Intel 和 Apple Silicon 使用同一个包，无需 Go / Node.js。此测试包只有 ad-hoc 本地完整性签名，不含 Apple Developer ID 签名或公证；系统可能提示无法验证开发者。不要全局关闭 Gatekeeper，遇到安全提示先核对下载来源与校验值，再由你按 macOS 的安全提示决定是否允许打开。详细步骤见[安装指南](INSTALL.md)。

首次测试建议验证窗口、托盘显示与恢复、连接 / 断开后的系统代理、订阅更新和退出恢复。构建通过不等于已完成 Mac 图形桌面和实际代理验收。

## 9. 当前边界

可用 `node scripts/preview-desktop.mjs` 启动明确标记“演示”的浏览器交互验收页，端口默认 19435。它只模拟内存状态，不读取真实订阅、不启动内核、不更改系统代理；不能用该演示页面验证实际能否联网。

当前没有开机登录启动、自动升级、签名公证、二维码扫描和实时流量曲线。右上角 `+` 是订阅添加，不冒充扫码。托盘原生适配封装在 `desktop/internal/tray`，不向根模块添加图形依赖、不替换 Wails 主循环。Mac / Linux 的托盘尚待原生实机验收；完整 Web 保持独立，不为紧凑桌面删减 Web 功能。
